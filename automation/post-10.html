매주 월요일 오전이나 월말 결산 시기가 되면 영업, 자재, 품질 부서 담당자들은 수십 개의 협력사 및 지점 엑셀 파일을 열어 복사·붙여넣기로 마스터 시트를 만듭니다. 이 과정에서 수식이 깨지거나, 숫자 컬럼에 공백 문자가 섞여 들어가거나, 기존 데이터를 덮어쓰는 휴먼 에러가 반복됩니다.

1. 현업 부서의 엑셀 취합 업무가 야근을 유발하는 구조적 원인

사람이 눈으로 수만 행의 데이터를 대조하는 방식은 검증 한계가 명확합니다. 자동화 도구를 만들 때 흔히 범하는 실수는 엑셀 프로그램을 백그라운드에서 직접 띄우는 Microsoft.Office.Interop.Excel 방식을 사용하는 것입니다. 서버 환경에 오피스가 설치되어 있지 않으면 동작하지 않을뿐더러, 프로세스 종료 누락 시 메모리 좀비가 쌓여 서버를 마비시킵니다.

2. Excel Interop을 버리고 스트림 파서(ExcelDataReader)를 써야 하는 이유

고속 자동화 파이프라인은 엑셀 파일을 오피스 문서가 아닌 압축된 XML 바이너리 스트림으로 직접 읽어야 합니다.

  • 오피스 미설치 환경 독립 실행: ExcelDataReader나 ClosedXML 같은 순수 .NET 스트림 라이브러리를 사용하면 엑셀이 없는 윈도우 서비스나 리눅스 컨테이너에서도 10만 행을 0.5초 만에 메모리 DataTable로 읽어 들입니다.
  • 사전 스키마 및 데이터 타입 검증: DB로 넘기기 전 필수 컬럼 존재 여부, 날짜 형식 오류, 음수 단가 등 비즈니스 룰 위반 행을 메모리에서 즉시 걸러내어 오류 행 번호와 사유가 담긴 리포트 파일을 담당자에게 자동 회신합니다.

3. SqlBulkCopy와 MERGE INTO를 결합한 무결점 Upsert 아키텍처

검증이 끝난 10만 건의 데이터를 운영 테이블에 반영할 때 반복문으로 INSERT 쿼리를 10만 번 날리면 네트워크 왕복 비용과 트랜잭션 로그 폭증으로 수 분이 걸립니다.

2단계 고속 스테이징 파이프라인:
① 1단계(Bulk Load): SqlBulkCopy를 이용해 인덱스 없는 임시 스테이징 테이블(#Temp_Import)로 10만 건을 1초 이내에 일괄 밀어 넣습니다.
② 2단계(Atomic Merge): DB 내부에서 MERGE INTO 단일 세트 연산으로 기존 키가 존재하면 UPDATE, 신규 키면 INSERT를 원자적 트랜잭션으로 일괄 반영합니다.

4. 처리 방식별 10만 건 데이터 적재 성능 비교

적재 방식 10만 행 처리 시간 및 안정성
행 단위 반복 INSERT 약 45초 ~ 120초 소요, 중간 실패 시 부분 반영 위험 높음
ORM(EF Core) AddRange 약 12초 ~ 20초 소요, 변경 추적(Change Tracking) 메모리 점유 급증
SqlBulkCopy + MERGE 약 1.2초 이내 완료, 단일 트랜잭션 롤백 보장으로 데이터 정합성 100% 확보

반복적인 엑셀 취합 업무를 스트림 파싱과 벌크 적재 파이프라인으로 전환하면 수 시간 걸리던 마감 작업이 파일 드롭 후 2초 만에 끝나는 완전 자동화 공정으로 탈바꿈합니다.
