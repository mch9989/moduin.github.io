업무 자동화 프로젝트를 제안할 때 가장 먼저 부딪히는 벽은 기술적 난이도가 아니라 사내 보안 정책(DLP)입니다. 설계 도면, 거래처 단가표, 설비 장애 이력 보고서 같은 핵심 업무 문서에는 대외비 정보가 포함되어 있어 외부 상용 클라우드 API로 원문 텍스트를 전송하는 것 자체가 규정 위반이 됩니다.

1. 기업 현장에서 클라우드 LLM API 도입이 가로막히는 결정적 이유

방화벽으로 외부 인터넷이 차단된 망분리 환경이나 중견 제조기업의 내부 서버에서는 외부 API 엔드포인트 호출 자체가 불가능합니다. 이 한계를 돌파하려면 사내 워크스테이션이나 내부 GPU 서버에 경량 언어 모델(SLM, 7B~14B 파라미터 수준)을 직접 올려 폐쇄망 내부에서만 추론이 완결되도록 파이프라인을 구성해야 합니다.

2. 비정형 문서(PDF·DOCX·XLSX) 텍스트 추출 및 청킹(Chunking) 전략

언어 모델에 파일을 통째로 던져주면 컨텍스트 윈도우 초과로 앞뒤 문맥이 잘리거나 환각(Hallucination)이 급증합니다. 전처리 레이어에서 반드시 문서 구조별 정규화를 거쳐야 합니다.

문서 포맷별 전처리 파이프라인:
① PDF 및 워드 문서: 표(Table) 레이아웃이 깨지지 않도록 마크다운 표 형식으로 변환 추출
② 엑셀 시트: 빈 행과 병합 셀을 평탄화(Flatten)한 뒤 헤더 키-값 쌍으로 직렬화
③ 스캔 이미지 문서: 로컬 OCR 엔진을 선행 통과시켜 텍스트 레이어를 입힌 후 추론 큐로 전달

3. 로컬 추론 서버(Ollama)와 JSON 스키마 강제 출력 설계

업무 자동화 프로그램이 AI의 응답을 받아 후속 DB 적재나 파일 이동으로 연결하려면, 모델이 사람처럼 줄글로 대답하게 두어서는 안 됩니다. 반드시 결정론적 JSON 포맷(Structured Outputs)으로만 응답하도록 강제해야 합니다.

  • Temperature 0.0 고정: 창의적 문장 생성을 차단하고 입력 문서에 명시된 팩트만 추출하도록 샘플링 온도를 0으로 고정합니다.
  • 정규식 및 스키마 후검증: 추출된 JSON에서 문서 유형(견적서/장애보고서/계약서), 발행일자, 핵심 키워드, 담당 부서 필드가 누락되었는지 백엔드 파서가 2차 검증한 뒤 사내 문서관리 DB에 자동 인덱싱합니다.

4. 하드웨어 VRAM 규모별 실무 모델 선정 및 배치 처리 기준

사내 서버 / PC 사양 권장 로컬 모델 및 운영 방식
VRAM 8GB GPU (GTX 1070Ti / RTX 3060급) 4-bit 양자화(Q4_K_M)된 7B~8B 한국어 특화 모델을 상주시킨 야간 배치(Batch) 문서 분류 및 태깅
VRAM 16GB~24GB GPU (RTX 4080 / 4090급) 14B급 모델 구동으로 장문 기술 보고서 요약, 조항 비교 및 사내 RAG 검색 응답 실시간 처리
운영 안정성 확보 기준 단일 프로세스 동시 요청(Concurrency)을 1~2개로 제한하여 GPU 메모리 OOM(Out of Memory) 방지

거대한 초거대 모델이 아니더라도, 잘 정제된 로컬 파서와 8B급 경량 모델만 결합하면 사내 공유 폴더에 방치되던 수만 건의 비정형 문서를 외부 유출 걱정 없이 살아있는 데이터베이스로 전환할 수 있습니다.
