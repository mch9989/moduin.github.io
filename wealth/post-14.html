[거시·데이터] ECOS·FRED 오픈 API를 활용한 금리·환율·유동성 시계열 DB 자동 구축기

⚠️ [필독] 법적 고지 및 투자 유의사항 (Disclaimer)

본 칼럼은 공개된 거시경제 통계 API를 수집·정제하는 소프트웨어 엔지니어링 파이프라인을 다룹니다.

특정 금융투자상품의 매수·매도를 권유하거나 개별 종목에 대한 투자 자문 및 조언을 제공하지 않습니다.

모든 투자의 의사결정과 손익 책임은 전적으로 투자자 본인에게 귀속됩니다.

목차
  • 1. 뉴스 헤드라인이 아닌 원천 시계열 데이터를 직접 적재해야 하는 이유
  • 2. 한국은행(ECOS)과 미국 연준(FRED) API 연동 아키텍처
  • 3. 휴장일 결측치(Null) 보간과 일·월 주기 데이터 정렬 기법
  • 4. 자동 수집 대상 핵심 매크로 지표 및 활용 기준표

매일 아침 증권사 시황 리포트나 경제 뉴스를 읽다 보면 같은 지표를 두고도 해석이 정반대로 갈리는 경우가 허다합니다. 객관적인 자산 배분과 리스크 관리를 수행하려면 누군가 가공해 놓은 뉴스 텍스트가 아니라, 중앙은행이 발표하는 원천 시계열 데이터를 내 로컬 데이터베이스에 직접 쌓아두고 정량적으로 비교할 수 있어야 합니다.

1. 뉴스 헤드라인이 아닌 원천 시계열 데이터를 직접 적재해야 하는 이유

한국은행 경제통계시스템(ECOS)과 미국 세인트루이스 연방준비은행(FRED)은 무료 인증키만으로 수만 종의 거시경제 시계열 데이터를 JSON/XML 형태로 개방하고 있습니다. 이를 매일 아침 스케줄러로 자동 수집해 두면 엑셀 수작업 없이도 한미 금리 역전 폭이나 실질금리 추이를 즉시 쿼리할 수 있습니다.

2. 한국은행(ECOS)과 미국 연준(FRED) API 연동 아키텍처

  • 메타데이터 기반 수집기: 지표 코드(예: DGS10, T10Y2Y, 722Y001)를 코드에 하드코딩하지 않고 DB의 MACRO_MASTER 테이블에 등록해 두어, 새로운 경제 지표를 추가할 때 코드 수정 없이 행(Row)만 추가하면 자동 수집되도록 설계합니다.
  • 증분 수집(Incremental Load): 매일 10년 치 전체 데이터를 다시 내려받지 않고, 각 지표별 마지막 적재 일자(MAX(BASE_DATE)) 이후 구간만 API 파라미터로 요청해 트래픽과 응답 시간을 최소화합니다.

3. 휴장일 결측치(Null) 보간과 일·월 주기 데이터 정렬 기법

한국과 미국의 공휴일이 다르기 때문에 두 국가의 시계열 데이터를 날짜 기준으로 조인(JOIN)하면 한쪽 값이 비어 있는 결측치가 발생합니다.

시계열 정렬 및 보간 규칙:
① 휴장일로 인해 당일 데이터가 . 또는 Null로 반환되는 경우, 직전 영업일의 유효 확정값을 이월(Forward-Fill)하여 스프레드 계산 오류를 방지합니다.
② 소비자물가지수(CPI)나 M2 통화량처럼 월 단위로 발표되는 지표는 발표 확정일 기준으로 일별 캘린더 테이블에 매핑하여 백테스트 시 미래참조 편향이 섞이지 않도록 관리합니다.

4. 자동 수집 대상 핵심 매크로 지표 및 활용 기준표

데이터 소스 핵심 지표 코드 및 관측 목적
FRED (미국 연준) DGS10 (미 국채 10년물 금리), T10Y2Y (10년-2년 장단기 금리차), BAMLH0A0HYM2 (하이일드 스프레드)
ECOS (한국은행) 기준금리, 국고채 3년·10년물 수익률, 원/달러 종가 환율, 광의통화(M2) 평잔 추이
파생 연산 지표 한미 국채 10년물 금리 스프레드 및 실질금리(명목금리 - 기대인플레이션) 자동 산출 뷰(View)

매일 아침 자동으로 갱신되는 거시경제 데이터베이스는 감정에 휘둘리는 뇌동매매를 막아주고, 현재 시장이 유동성 확장 국면인지 긴축 경계 국면인지를 수치로 판단하게 해주는 가장 객관적인 나침반이 됩니다.
