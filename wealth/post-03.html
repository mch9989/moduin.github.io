증권사 OpenAPI 연동 기반 C# 퀀트 스크리닝 시스템 아키텍처

작성일: 2026년 11월 5일 · 작성자: moduin · 읽는 시간: 약 8분

목차

  • 1. 정량적 투자 시스템 구축이 필요한 이유
  • 2. 레거시 COM(ActiveX)과 비동기 백엔드의 결합
  • 3. TR 초당 전송 제한: 토큰 버킷(Token Bucket) 제어기
  • 4. 고속 시세 수집을 위한 생산자-소비자(Producer-Consumer) 패턴
  • 5. 백테스팅을 위한 시계열 DB 적재 및 모니터링

감정에 휘둘리는 매매를 배제하고 원칙적인 자산 배분을 실현하려면 정량적 재무 지표와 가격 모멘텀을 실시간으로 추적하는 시스템이 필수적입니다. 국내 대다수 증권사 API는 여전히 32비트 COM(ActiveX) 모듈 기반으로 동작하기 때문에 고속 멀티스레드 환경과의 결합 시 병목이 발생하기 쉽습니다. 본 글에서는 C# .NET 환경에서 안정적인 퀀트 스크리닝 엔진을 구축한 설계 과정을 공유합니다.

1. 정량적 투자 시스템 구축이 필요한 이유

시장에는 2,500개가 넘는 종목이 존재하며 장중 쏟아지는 시세 틱(Tick) 데이터는 사람의 인지 한계를 넘어섭니다. ROE, 부채비율, 영업이익률 등 기본적 펀더멘털과 이동평균선, 볼린저 밴드 등 기술적 지표를 결합한 스크리닝을 완전 무인으로 가동하는 것이 시스템 구축의 주 목적입니다.

2. 레거시 COM(ActiveX)과 비동기 백엔드의 결합

증권사 API의 핵심 문제는 단일 스레드 아파트먼트(STA) 모델에서만 이벤트가 발생한다는 점입니다. 무거운 수식 계산이나 DB 저장을 이벤트 핸들러(OnReceiveTrData) 내부에서 직접 수행하면 윈도우 폼 전체가 굳어버리며 패킷 누락이 발생합니다.

[증권사 서버] ──(시세 틱 발생)──► [STA 메인 UI 스레드 (ActiveX 수신)]
                                              │
                                              ▼ (순수 데이터만 추출 후 즉시 반환)
                                  [ConcurrentQueue<TickData>]
                                              │
                    ┌─────────────────────────┴─────────────────────────┐
                    ▼                                                   ▼
       [워커 스레드 1: 퀀트 지표 산출]                      [워커 스레드 2: SQLite 시계열 적재]
       (이동평균, RSI, 돌파 시그널)                         (전일 대비 거래량 집계)

3. TR 초당 전송 제한: 토큰 버킷(Token Bucket) 제어기

핵심 제약 사항: 증권사는 과도한 시세 조회를 막기 위해 1초당 조회 횟수를 엄격히 제한(예: 초당 5회)하며, 이를 위반할 경우 즉시 IP 차단이나 세션 종료 페널티를 부과합니다.

무조건 Thread.Sleep()을 주는 비효율적인 방식 대신, 아래와 같이 정밀한 토큰 버킷(Token Bucket) 레이트 리미터를 C#으로 구현하여 처리량을 극대화합니다.

public class TokenBucketRateLimiter
{
    private readonly int _maxTokens;
    private readonly double _refillRatePerMillisecond;
    private double _currentTokens;
    private DateTime _lastRefillTime;
    private readonly object _lock = new();

    public TokenBucketRateLimiter(int maxTokens, TimeSpan refillPeriod)
    {
        _maxTokens = maxTokens;
        _refillRatePerMillisecond = (double)maxTokens / refillPeriod.TotalMilliseconds;
        _currentTokens = maxTokens;
        _lastRefillTime = DateTime.UtcNow;
    }

    public async Task WaitForTokenAsync()
    {
        while (true)
        {
            lock (_lock)
            {
                var now = DateTime.UtcNow;
                var elapsed = (now - _lastRefillTime).TotalMilliseconds;
                _currentTokens = Math.Min(_maxTokens, _currentTokens + (elapsed * _refillRatePerMillisecond));
                _lastRefillTime = now;

                if (_currentTokens >= 1.0)
                {
                    _currentTokens -= 1.0;
                    return; // 요청 허용
                }
            }
            await Task.Delay(50); // 토큰 충전 대기
        }
    }
}

4. 고속 시세 수집을 위한 생산자-소비자 패턴

이벤트가 발생하는 즉시 System.Threading.Channels 또는 BlockingCollection<T>으로 밀어 넣고, 백그라운드 태스크가 이를 컨슘하여 퀀트 필터링 로직을 수행합니다. 이를 통해 장 시작 직후 시세가 폭발하는 구간에서도 UI 프리징 없이 초당 수만 건의 틱 데이터를 유실 없이 처리할 수 있습니다.
