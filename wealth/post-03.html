증권사 OpenAPI 연동 기반 C# 퀀트 스크리닝 시스템 아키텍처

작성일: 2026년 11월 5일 · 작성자: moduin · 읽는 시간: 약 9분

목차

  • 1. 문제 정의: 감정을 배제한 정량적 데이터 스크리닝의 필요성
  • 2. 전체 시스템 아키텍처 (생산자-소비자 패턴)
  • 3. 레거시 COM(OCX) 이벤트와 UI 스레드 프리징 분리
  • 4. 초당 호출 제한(TR Limit) 제어를 위한 토큰 버킷 알고리즘
  • 5. 시계열 데이터 DB 적재 및 백테스팅 파이프라인

개인 투자자가 금융 시장에서 장기적으로 살아남기 위해 가장 경계해야 할 적은 시장의 변동성이 아니라 본인의 감정과 편향입니다. 주관적 뉴스나 호재에 휘둘리지 않고 철저한 계량 데이터에 기반해 종목을 발굴하기 위해서는 독자적인 스크리닝 시스템이 필요합니다. 본 글에서는 국내 레거시 증권사 OpenAPI(키움증권 등)와 C# .NET 환경을 결합해 실시간 시세를 수집하고 조건식으로 필터링하는 실무 아키텍처를 소개합니다.

1. 문제 정의: 감정을 배제한 정량적 데이터 스크리닝의 필요성

국내 상장 종목 2,500여 개를 대상으로 PER, PBR, 영업이익률, 모멘텀 지표, 외인/기관 순매수 수급을 수동으로 점검하는 것은 물리적으로 불가능합니다. HTS 기본 조건검색은 복합적인 시계열 통계나 과거 특정 국면에서의 백테스팅을 유연하게 검증하는 데 한계가 있습니다. 결국 자체 시스템을 통해 로우 데이터를 직접 쥐고 있어야 원하는 로직을 제약 없이 구동할 수 있습니다.

2. 전체 시스템 아키텍처 (생산자-소비자 패턴)

증권사 API의 초당 전송 제한과 고속 틱(Tick) 데이터 수신 환경에서 윈도우 폼이 멈추지 않도록 스레드를 완전 분리한 생산자-소비자(Producer-Consumer) 아키텍처입니다.

[증권사 서버 (OpenAPI 서버)]
          │ (실시간 시세 수신 / TR 응답)
          ▼
[1. STA 스레드 (COM ActiveX 이벤트 핸들러)] ──► UI 블로킹 원천 배제
          │
          ▼ (원시 패킷 고속 Enqueue)
[2. 인메모리 버퍼: ConcurrentQueue<MarketTickData>]
          │
          ├─────────────────────────────────────────┐
          ▼ (Background Worker Task 1)              ▼ (Background Worker Task 2)
[3. 기술적 지표 / 수급 퀀트 필터링 엔진]     [4. SQLite / MS-SQL 시계열 적재]
          │
          ▼ (조건 부합 종목 검출 시)
[5. 실시간 UI 대시보드 알림 (Invoke) 및 텔레그램 전송]

3. 레거시 COM(OCX) 이벤트와 UI 스레드 프리징 분리

국내 주요 증권사 모듈은 여전히 32비트 기반의 STA(Single-Threaded Apartment) COM 인터페이스로 구동됩니다. 데이터 수신 이벤트인 OnReceiveTrData나 OnReceiveRealData 내부에서 무거운 지표 계산, LINQ 필터링, DB 저장을 직접 수행하면 UI 메시지 펌프가 멈춰 화면 전체가 '응답 없음' 상태에 빠집니다.

// 1. 이벤트 핸들러에서는 순수 데이터만 추출하여 큐로 넘김
private void axKHOpenAPI_OnReceiveTrData(object sender, AxKHOpenAPILib._DKHOpenAPIEvents_OnReceiveTrDataEvent e)
{
    // 긴 연산 금지: 원시 텍스트만 파싱하여 즉시 객체화
    var price = int.Parse(axKHOpenAPI.GetCommData(e.sTrCode, e.sRQName, 0, "현재가").Trim().Replace("-", ""));
    var volume = long.Parse(axKHOpenAPI.GetCommData(e.sTrCode, e.sRQName, 0, "거래량").Trim());

    _tickQueue.Enqueue(new RawMarketData 
    { 
        ItemCode = e.sRQName, 
        Price = price, 
        Volume = volume, 
        ReceivedTime = DateTime.Now 
    });
}

// 2. 백그라운드 태스크에서 비동기로 큐를 소비하며 퀀트 연산 수행
private async Task ProcessMarketDataAsync(CancellationToken ct)
{
    while (!ct.IsCancellationRequested)
    {
        if (_tickQueue.TryDequeue(out var data))
        {
            // 이동평균, 볼린저밴드, 수급 모멘텀 스코어링 계산
            EvaluateQuantStrategy(data);
        }
        else
        {
            await Task.Delay(10, ct); // CPU 과점 방지
        }
    }
}

4. 초당 호출 제한(TR Limit) 제어를 위한 토큰 버킷 알고리즘

핵심 트러블슈팅: 증권사 API는 통상 '1초당 5회', '1시간당 1,000회' 등 엄격한 TR 제한을 둡니다. 이를 위반하면 프로그램이 강제 접속 종료(블랙리스트) 처리됩니다.

단순 Thread.Sleep은 요청 간격을 경직되게 만들어 전체 조회 시간을 불필요하게 늘립니다. 정교한 토큰 버킷(Token Bucket) 알고리즘을 구현하여 허용 범위 내에서 순간 버스트(Burst) 요청을 처리하면서도 초당 제한을 절대 초과하지 않도록 호출기를 설계해야 합니다.

5. 시계열 데이터 DB 적재 및 백테스팅 파이프라인

수집된 호가 잔량 및 틱 데이터는 일 단위 파티셔닝된 SQLite 또는 로컬 MS-SQL에 기록됩니다. 데이터가 축적되면 "코스피 지수가 20일선 아래에 위치할 때 저PBR 고ROE 종목의 5일 보유 수익률"과 같은 전략을 과거 데이터로 신속히 검증하는 자체 백테스팅 엔진의 밑거름이 됩니다.
