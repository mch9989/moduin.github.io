스마트팩토리 & MES

제조 현장 레거시 시스템과 MES 연동 시 반드시 체크할 데이터 아키텍처

작성일: 2026년 11월 5일 · 작성자: moduin

수십 년간 가동된 제조 공장에 차세대 스마트팩토리 시스템이나 MES(제조실행시스템)를 도입할 때 가장 큰 장벽은 신규 기술이 아니라, 기존의 '레거시(Legacy) 시스템'과의 인터페이스 정합성입니다.

핵심 요약: 설비 PLC나 레거시 DB와의 직접 커넥션은 장애 전파의 주원인입니다. 중간 완충 버퍼(Staging DB 또는 Queue)를 설계하고 데이터 멱등성을 보장해야 라인 중단을 방지할 수 있습니다.

1. 직접 결합(Direct Connection)의 위험성

개발 편의성을 이유로 상위 MES 서버가 현장 설비 PC나 구형 DB에 직접 SELECT/INSERT 쿼리를 날리도록 설계하는 실수를 자주 범합니다. 이 방식은 네트워크 단선이나 레거시 DB의 락(Lock) 경합 발생 시 즉시 생산 라인 정지로 이어집니다.

2. 스테이징(Staging) 인터페이스 테이블 설계

안정적인 연동을 위해 반드시 지켜야 할 기본 아키텍처 원칙입니다:

  • 단방향 플래그 기반 처리: 원본 데이터에 직접 손대지 않고 IF_FLAG ('N' -> 'P' -> 'Y' / 'E') 패턴의 상태 머신을 둡니다.
  • 트랜잭션 격리: 대량의 실적 집계 쿼리가 현장 수집 프로세스를 블로킹하지 않도록 NOLOCK 힌트 또는 Read-Committed Snapshot 격리 수준을 분리합니다.
  • 네트워크 단절 대비 로컬 버퍼링: 현장 게이트웨이 PC에 경량 버퍼(SQLite, File Queue 등)를 두어 통신 복구 시 누락 없이 재전송되도록 구현합니다.

3. 멱등성(Idempotency)의 중요성

공정 데이터 전송 중 타임아웃이 발생해 동일한 바코드 스캔이나 생산 실적이 재전송되었을 때, 중복으로 적재되지 않도록 유니크 키(라인 ID + 설비코드 + 타임스탬프 + 시퀀스)를 통한 중복 검증 로직이 시스템 레벨에 내장되어야 합니다.
