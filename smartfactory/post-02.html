스마트팩토리 & MES

제조 현장 레거시 시스템과 MES 연동 시 반드시 체크할 데이터 아키텍처

수십 년간 가동된 제조 공장에 차세대 스마트팩토리 시스템이나 MES(Manufacturing Execution System)를 도입할 때 가장 큰 난관은 신기술 적용이 아니라, 현장에서 이미 24시간 돌아가고 있는 기존 '레거시(Legacy) 시스템'과의 인터페이스 정합성 확보입니다. 본 글에서는 라인 정지 위험 없이 안전하게 데이터를 통합하는 실무 아키텍처 원칙을 다룹니다.

1. 문제 정의: 레거시 인터페이스와 공정 중단의 위험

제조 현장의 레거시 시스템은 대부분 구형 하드웨어와 단종된 DBMS(예: Oracle 9i, MS-SQL 2000 등)에서 운용되는 경우가 흔합니다. 이러한 환경에 최신 MES가 대량의 생산 실적이나 자재 투입 트랜잭션을 무작정 요청하게 되면, CPU 병목이나 테이블 락(Lock) 경합으로 인해 설비 인터락(Interlock)이 걸리며 라인 전체가 멈추는 대형 사고로 이어집니다.

2. 안티패턴: 직접 연결(Direct DB Link)의 치명적 결함

개발 기간 단축을 위해 상위 MES 서버가 현장 설비 PC나 구형 DB에 직접 SELECT/INSERT 쿼리를 날리도록 설계하는 것은 대표적인 안티패턴입니다.

[나쁜 예: 직접 결합 방식]
 상위 MES ──(직접 쿼리 실행)──► 레거시 설비 DB
   * 문제점: 쿼리 지연 발생 시 설비 PLC 인터페이스까지 프리징되어 라인 정지!

[권장 예: 비동기 완충 버퍼 방식]
 상위 MES ◄──[Staging DB / Message Queue] ◄── 현장 게이트웨이 ◄── 설비 PLC
   * 장점: 네트워크가 끊기거나 레거시가 지연되어도 중간 버퍼가 흡수하여 설비는 정상 가동

3. 완충형 스테이징(Staging) 인터페이스 아키텍처

현장 설비와 상위 시스템 간의 결합도를 낮추기 위해 반드시 중간 완충 테이블(Staging Table)을 두고 단방향 플래그 기반의 상태 머신을 구축해야 합니다.

-- 표준 인터페이스 테이블 스키마 설계 예시
CREATE TABLE IF_EQUIP_PRODUCTION_ACTUAL (
    IF_ID BIGINT IDENTITY(1,1) PRIMARY KEY,
    FACTORY_CODE VARCHAR(10) NOT NULL,
    LINE_ID VARCHAR(20) NOT NULL,
    EQUIP_ID VARCHAR(20) NOT NULL,
    LOT_ID VARCHAR(50) NOT NULL,
    PRODUCT_QTY INT NOT NULL,
    EVENT_DTTM DATETIME NOT NULL,
    
    -- 상태 제어 플래그 ('N': 신규, 'P': 처리중, 'Y': 성공, 'E': 에러)
    IF_FLAG CHAR(1) DEFAULT 'N' NOT NULL,
    RETRY_COUNT INT DEFAULT 0 NOT NULL,
    ERROR_MSG NVARCHAR(500) NULL,
    CREATE_DTTM DATETIME DEFAULT GETDATE(),
    PROCESS_DTTM DATETIME NULL
);

CREATE INDEX IDX_IF_STATUS ON IF_EQUIP_PRODUCTION_ACTUAL (IF_FLAG, EVENT_DTTM);

4. 데이터 멱등성(Idempotency)과 상태 머신 설계

핵심 설계 원칙: 동일한 바코드 스캔이나 생산 실적이 네트워크 타임아웃으로 인해 2번 이상 수신되더라도, 시스템 상의 재고나 실적은 오직 1번만 집계되어야 합니다.

이를 위해 [설비코드 + LOT_ID + 공정시퀀스 + 발생시간]으로 구성된 복합 비즈니스 키를 생성하고, 상위 적재 시 중복 여부를 먼저 검증하는 멱등성(Idempotency) 필터를 통과시킵니다.

5. 네트워크 단절 대비 로컬 버퍼링과 복구 전략

공장 내 스위칭 허브 장애나 케이블 단선으로 상위 네트워크가 끊기더라도 생산은 계속되어야 합니다. 현장 게이트웨이 PC에 경량 임베디드 DB(SQLite)나 파일 기반 큐를 두어 로컬에 선 적재한 후, 연결 복구 시 지수 백오프(Exponential Backoff) 알고리즘으로 상위 스테이징 테이블로 순차 방출하는 Fail-over 아키텍처가 필수적입니다.
