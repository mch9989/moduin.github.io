스마트팩토리 & MES

제조 현장 레거시 시스템과 MES 연동 시 반드시 체크할 데이터 아키텍처

  • 5. 네트워크 단선 시 현장 엣지(Edge) 로컬 복구 전략

수십 년간 쉼 없이 돌아가는 제조 공장에 스마트팩토리 고도화 프로젝트나 차세대 MES(Manufacturing Execution System)를 도입할 때 마주치는 최대 난제는 최신 클라우드 기술이 아니라 '오래된 레거시 시스템 및 구형 PLC와의 정합성'입니다. 현장에서는 단 5분의 시스템 지연도 라인 셧다운과 막대한 생산 손실로 이어집니다. 본 글에서는 레거시 공장의 제약을 극복하고 무중단 데이터 파이프라인을 구축했던 실무 아키텍처 노하우를 정리합니다.

1. 도입 배경: 레거시(Legacy) 공장의 현실과 딜레마

이상적인 스마트팩토리 구축 가이드는 모든 설비가 표준 OPC UA나 최신 REST API를 지원한다고 가정하지만, 실제 공장 라인에는 윈도우 XP/7 시절에 도입된 제어 PC, 폐쇄망 오라클 9i/10g DB, 시리얼(RS-232/485) 통신에만 의존하는 장비들이 혼재되어 있습니다. 설비 교체 없이 상위 중앙 MES와 통신을 뚫어야 하는 상황에서 시스템 안정성을 확보하는 것이 핵심 과제입니다.

2. 안티패턴: 직접 커넥션(Direct Connection)의 치명적 결함

가장 위험한 접근 방식은 상위 MES 애플리케이션 서버가 현장 설비 DB나 제어 PC에 직접 DB Connection Pool을 열고 SELECT / INSERT를 날리는 구조입니다.

  • Lock 경합 및 블로킹: 상위 시스템의 대용량 분석 쿼리가 현장의 실시간 트랜잭션을 락(Lock)으로 묶어버리면 바코드 스캔이나 라벨 발행이 멈춥니다.
  • 단일 장애점(SPOF): 현장 설비 PC가 재부팅되거나 스위칭 허브가 다운될 경우 상위 MES 서버의 커넥션 스레드가 고갈되어 전체 공장 서비스가 중단됩니다.

3. 완충 버퍼 계층(Staging & Queue) 아키텍처 설계

설비와 MES의 물리적·논리적 강결합을 끊어내기 위해 반드시 중간 완충 계층(Staging Interface Table 또는 In-Memory Queue)을 배치해야 합니다.

[현장 PLC / 바코드 스캐너]
           │ (생산 실적 발생)
           ▼
[엣지 PC (C# Collector Agent)] ──(단선 시)──► [로컬 SQLite 캐시 저장]
           │                                           │
           ▼ (정상 연결 시)                               │ (망 복구 시 동기화)
[Staging DB (단방향 인터페이스 테이블)] ◄────────────────┘
   - IF_FLAG: 'N'(신규) -> 'P'(처리중) -> 'Y'(완료) / 'E'(오류)
           │
           ▼ (비동기 배치 워커가 주기적 Poll)
[중앙 엔터프라이즈 MES 코어 엔진]

4. 데이터 무결성과 멱등성(Idempotency) 보장 메커니즘

현장 실무 원칙: 네트워크 타임아웃으로 인해 동일한 생산 실적 패킷이 2회 이상 재전송되더라도 DB에는 반드시 1회만 반영되어야 합니다. 이것이 멱등성 설계입니다.

인터페이스 테이블 설계 시 복합 유니크 인덱스를 지정하여 중복 적재를 원천 차단하고, 처리 상태 머신(State Machine)을 트랜잭션 단위로 묶어 처리합니다.

-- 멱등성을 보장하는 스테이징 테이블 처리 프로시저 패턴 예시
BEGIN TRANSACTION;

-- 1. 아직 처리되지 않은 레코드 100건을 비관적 락으로 점유 (경합 방지)
WITH CTE AS (
    SELECT TOP (100) IF_SEQ, IF_FLAG
    FROM TB_MES_IF_STAGING WITH (UPDLOCK, READPAST)
    WHERE IF_FLAG = 'N'
    ORDER BY CREATE_DTTM ASC
)
UPDATE CTE
SET IF_FLAG = 'P' -- '처리중'으로 마킹
OUTPUT inserted.IF_SEQ;

-- 2. 실제 MES 생산 실적 마스터 테이블로 데이터 병합 (UPSERT / MERGE)
-- 3. 정상 처리 완료 시 IF_FLAG = 'Y', 실패 시 'E' 및 에러 로그 기록

COMMIT TRANSACTION;

5. 네트워크 단선 시 현장 엣지(Edge) 로컬 복구 전략

공장 내 간선 케이블 포설 구간이나 무선 AGV 라인은 일시적인 패킷 드롭이 필연적입니다. C# 기반 엣지 에이전트 내부에는 Polly 라이브러리를 활용한 지수 백오프 재시도(Exponential Backoff)를 구현하고, 3회 이상 실패 시 현장 SSD의 로컬 임베디드 DB(SQLite)로 저장 위치를 즉시 페일오버(Failover)하는 로직을 반드시 탑재해야 합니다.
