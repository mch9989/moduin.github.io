스마트팩토리 구축 프로젝트가 완료된 직후에는 모든 시스템이 매끄럽게 돌아갑니다. 하지만 라인이 본격 가동되고 생산 이력(Lot History)과 설비 센서 데이터가 수천만 건 이상 누적되는 6개월 시점부터 현업에서는 동일한 장애 신고가 올라오기 시작합니다. "현장 POP 단말기에서 바코드를 찍었는데 화면이 멈추고 '트랜잭션이 교착 상태(Deadlock)에 빠졌습니다'라는 에러 팝업이 뜹니다."

일반 사무용 웹 서비스와 달리 제조 현장의 MES(제조실행시스템) 데이터베이스는 초단위로 쏟아지는 설비 자동 실적 수집(INSERT/UPDATE)과 관리자 대시보드의 대용량 집계 조회(SELECT)가 동일한 핵심 테이블을 동시에 타격합니다. 하드웨어 사양을 아무리 높여도 잠금(Lock) 메커니즘과 인덱스 구조를 바로잡지 않으면 라인 정지로 직결됩니다.

1. 가동 초기엔 멀쩡하던 MES가 6개월 뒤 멈추는 이유

초기 데이터가 수만 건 수준일 때는 인덱스가 부실하더라도 DB 엔진이 테이블 전체를 스캔(Table Scan)하는 데 0.05초밖에 걸리지 않습니다. 잠금을 쥐고 있는 시간이 워낙 짧아 동시성 충돌이 겉으로 드러나지 않을 뿐입니다.

그러나 데이터가 수천만 건을 넘어가면 조회 쿼리의 실행 시간이 2~3초 이상으로 늘어납니다. 이 3초 동안 공유 잠금(Shared Lock)이 테이블의 광범위한 페이지(Page)를 점유하게 되고, 그 사이 현장의 PLC 수집기가 배타적 잠금(Exclusive Lock)을 걸어 실적을 기록하려다 서로의 자원을 기다리며 교착상태에 빠지게 됩니다.

2. 제조 현장에서 교착상태(Deadlock)가 폭발하는 3대 패턴

현업 MES 운영 과정에서 가장 빈번하게 관찰되는 교착상태 유발 시나리오는 크게 세 가지입니다.

패턴 1: 작업지시(Work Order) 마스터 테이블의 역순 갱신
현장 POP 단말기는 [Lot 실적 테이블 INSERT → 작업지시 누적수량 UPDATE] 순서로 트랜잭션을 처리하는 반면, 생산관리자의 ERP 연동 배치는 [작업지시 상태 UPDATE → Lot 실적 상태 UPDATE] 순서로 접근하면서 두 트랜잭션이 서로의 잠금을 무한 대기합니다.

패턴 2: 외래 키(Foreign Key) 인덱스 누락으로 인한 테이블 잠금 확대
부모 테이블의 기준정보를 수정하거나 삭제할 때 자식 테이블의 외래 키 컬럼에 인덱스가 없으면, DB 엔진은 무결성 검증을 위해 자식 테이블 전체에 잠금을 걸어버립니다.

패턴 3: 실시간 모니터링 전광판(Andon)의 무분별한 집계 쿼리
공장 현장 대형 모니터에 띄워둔 안돈(Andon) 대시보드가 5초마다 수백만 건의 당일 실적 테이블을 GROUP BY로 집계하면서 설비 인터페이스의 실시간 쓰기 작업을 가로막습니다.

3. 트랜잭션 격리 수준과 잠금(Lock) 경합 해소 전략

MS-SQL 기반의 중소·중견 제조 MES 환경에서 애플리케이션 코드를 전부 뜯어고치지 않고도 잠금 경합을 대폭 줄일 수 있는 핵심 데이터베이스 튜닝 포인트입니다.

  • RCSI(Read Committed Snapshot Isolation) 활성화: 기본 READ COMMITTED 격리 수준에서는 읽기 작업이 쓰기 작업을 차단합니다. DB 옵션에서 READ_COMMITTED_SNAPSHOT ON을 활성화하면 행 버전 관리(Row Versioning)를 통해 조회 쿼리가 쓰기 트랜잭션을 대기하지 않고 직전 커밋 데이터를 즉시 읽어옵니다.
  • 트랜잭션 내 테이블 접근 순서 표준화: 모든 저장 프로시저(Stored Procedure)와 백엔드 API에서 테이블을 갱신할 때는 반드시 [마스터 테이블 → 상세 이력 테이블] 순으로 일관된 순서를 강제해야 교차 잠금을 원천 차단할 수 있습니다.
  • 트랜잭션 범위 최소화: 외부 설비 통신이나 ERP API 호출 같은 네트워크 I/O 로직은 절대 DB 트랜잭션(BEGIN TRAN ~ COMMIT) 블록 내부에 포함시키지 말고, 데이터 검증이 끝난 직후 순수 DB 반영 구간만 0.1초 이내로 묶어야 합니다.

4. 실무 적용을 위한 테이블 파티셔닝 및 인덱스 설계 기준

튜닝 영역 현업 MES 표준 설계 기준
클러스터형 인덱스 빈번한 Insert가 발생하는 설비 로그 테이블은 랜덤 UUID 대신 순차 증가하는 IDENTITY 또는 (작업일자, 순번) 복합키로 설정하여 페이지 분할(Page Split) 방지
커버링 인덱스 현장 POP 조회 화면에서 자주 쓰이는 (라인코드, 작업일자) 조건에 INCLUDE (양품수량, 불량수량, 설비상태)를 포함하여 키 룩업(Key Lookup) 비용 제거
테이블 파티셔닝 월 단위 또는 분기 단위로 생산 이력 테이블을 파티셔닝(Partitioning)하여 당월 실시간 트랜잭션 영역과 과거 이력 조회 영역을 물리적으로 분리
전광판 데이터 분리 안돈(Andon) 대시보드는 운영 트랜잭션 테이블을 직접 SUM() 하지 않고, 1분 주기 스케줄러가 갱신하는 경량 요약 테이블(Summary Table)만 조회하도록 격리

스마트팩토리의 성패는 화려한 대시보드 화면이 아니라 3교대 24시간 돌아가는 생산 라인의 데이터를 단 1건의 지연이나 잠금 오류 없이 받아내는 데이터베이스의 기초 체력에서 갈립니다. 가동 전 부하 테스트 단계에서부터 RCSI 설정과 트랜잭션 순서 규약, 그리고 커버링 인덱스 설계를 표준화해 두어야 안정적인 무중단 공장을 운영할 수 있습니다.
