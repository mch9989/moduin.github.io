현대 스마트팩토리의 제조 라인에는 지멘스(Siemens), 미쓰비시(MELSEC), 오므론(Omron), LS일렉트릭 등 다양한 제조사의 PLC(Programmable Logic Controller)가 혼재되어 있습니다. 이들 장비에서 온도, 압력, 사이클 타임, 불량 카운트 데이터를 수집할 때마다 제조사 전용 프로토콜을 개별 구현하는 것은 극심한 유지보수 재앙을 초래합니다. 본 글에서는 산업 표준 통신 규격인 OPC UA(Open Platform Communications Unified Architecture)를 활용해 C# .NET 환경에서 견고한 데이터 수집 게이트웨이를 구축하는 방안을 다룹니다.

1. 배경: 설비 이기종 통신 프로토콜의 파편화 문제

과거의 OPC DA(Data Access)는 윈도우 OS의 DCOM 기술에 종속되어 있어 방화벽을 넘나드는 통신 설정이 매우 까다로웠고 보안 취약점이 컸습니다. 반면 OPC UA는 플랫폼 독립적인 TCP 기반 바이너리 프로토콜(opc.tcp)을 사용하며, 자체적인 x509 인증서 기반 암호화와 사용자 인증 계층을 완벽히 내장하고 있습니다.

2. OPC UA의 핵심 강점과 주소 공간 모델

OPC UA는 데이터를 단순한 메모리 번지(예: D100, M20)가 아니라, 계층 구조를 갖춘 노드(NodeId) 객체로 추상화합니다. 상위 애플리케이션은 ns=2;s=Line1.MachineA.SpindleSpeed와 같이 직관적인 네임스페이스와 식별자를 통해 설비 데이터를 탐색할 수 있습니다.

[다양한 현장 설비 PLC (지멘스, 미쓰비시, LS)]
               │ (독자 필드버스 프로토콜)
               ▼
[현장 OPC UA Server (Kepware, 설비 내장 서버)]
               │
               │ (opc.tcp 암호화 세션 / 4840 포트)
               ▼
[C# .NET 데이터 수집 게이트웨이 서비스]
   ├─► Session Manager (연결 상태 감시 / Keep-Alive)
   ├─► Subscription Manager (값 변경 이벤트 수신)
   └─► Data Dispatcher (인메모리 버퍼 ──► 상위 MES / TSDB 전송)

3. 폴링(Polling) 대신 구독(Subscription) 모델을 써야 하는 이유

1,000개의 센서 태그를 수집할 때 매초마다 타이머를 돌려 읽어오는 폴링 방식은 대역폭 낭비와 PLC CPU 과부하를 유발합니다. OPC UA의 구독(Subscription) 메커니즘을 사용하면, 서버 측에서 데이터가 실제로 변경되었을 때만(DataChangeNotification) 클라이언트로 이벤트를 푸시해주므로 트래픽을 90% 이상 절감할 수 있습니다.

4. C# OPC Foundation SDK 클라이언트 구현 실무

공식 Opc.Ua.Client 라이브러리를 활용해 세션을 생성하고 태그 변경 이벤트를 등록하는 실무 코드 구조입니다.

// 1. 엔드포인트 설정 및 세션 생성
var endpoint = new ConfiguredEndpoint(null, new EndpointDescription("opc.tcp://192.168.1.100:4840"));
var session = await Session.Create(config, endpoint, false, "moduin_Collector", 60000, new UserIdentity(), null);

// 2. 1000ms 간격의 구독(Subscription) 등록
var subscription = new Subscription(session.DefaultSubscription) 
{ 
    PublishingInterval = 1000, 
    PublishingEnabled = true 
};

// 3. 모니터링할 센서 노드 정의
var monitoredItem = new MonitoredItem(subscription.DefaultItem)
{
    DisplayName = "SpindleTemperature",
    StartNodeId = new NodeId("ns=2;s=Line1.Motor.Temperature"),
    AttributeId = Attributes.Value,
    SamplingInterval = 500 // 설비 내부 샘플링 주기
};

// 4. 값 변경 시 호출되는 이벤트 콜백 연결
monitoredItem.Notification += (item, e) =>
{
    if (e.NotificationValue is MonitoredItemNotification notification)
    {
        var val = notification.Value.WrappedValue.Value;
        var sourceTime = notification.Value.SourceTimestamp;
        // 인메모리 큐로 전달하여 상위 DB 적재
        _sensorBuffer.Enqueue(new SensorData("TEMP", val, sourceTime));
    }
};

subscription.AddItem(monitoredItem);
session.AddSubscription(subscription);
await subscription.CreateAsync();

5. 네트워크 단선 대비 자동 재접속(Auto Reconnect) 구현

현장 필수 예외 처리: 공장 현장은 용접 노이즈나 허브 순단으로 네트워크가 수시로 끊깁니다. Session.KeepAlive 이벤트를 감시하여 통신 실패를 감지하면, 즉시 기존 세션을 정리하고 백그라운드에서 지수 백오프(Exponential Backoff) 방식으로 안전하게 재연결을 시도해야 시스템 중단을 막을 수 있습니다.
