스마트팩토리 현장에는 미쓰비시(MELSEC), 지멘스(S7), LS산전(XGT), 오므론 등 다양한 제조사의 PLC가 존재합니다. 각 PLC마다 독자적인 시리얼 또는 이더넷 프로토콜을 개별 구현하는 방식은 설비 추가 시마다 개발 비용을 눈덩이처럼 불립니다. 본 글에서는 산업용 통신 표준인 OPC UA(Open Platform Communications Unified Architecture)를 도입하여 C# 기반 수집 시스템을 표준화한 과정을 설명합니다.

1. 표준 프로토콜의 필요성: 제조사 파편화 극복

OPC UA는 윈도우 종속적이었던 과거 OPC DA(DCOM 기반)의 한계를 벗어나 Linux, 임베디드, 클라우드 환경에서도 작동하며 방화벽 친화적인 바이너리 TCP(opc.tcp) 포트를 사용합니다. 인증서 교환을 통한 하드웨어 레벨 보안 암호화가 기본 내장되어 공장 내 보안 망 분리 요건을 만족합니다.

2. OPC UA 아키텍처: NodeId와 주소 공간 모델링

모든 설비의 센서값, 모터 RPM, 알람 상태는 계층적 객체 노드(NodeId)로 매핑됩니다. 예를 들어 ns=2;s=Line1.Furnace01.Temperature와 같이 네임스페이스와 문자열 키로 직관적인 탐색(Browse)이 가능합니다.

3. 폴링(Polling) 대 구독(Subscription) 모델 성능 비교

네트워크 최적화: 타이머를 돌려 매초 수천 개의 태그를 조회하는 폴링 방식은 대역폭을 낭비하고 PLC CPU에 과부하를 줍니다. 값이 실제로 변할 때만 이벤트를 밀어주는 Subscription & MonitoredItem 모델을 사용해야 합니다.

4. C# OPC UA 클라이언트 핵심 구현 코드

OPC Foundation 공식 .NET 라이브러리를 사용해 안전한 비동기 세션을 맺고 구독을 등록하는 프로덕션 레벨 코드 구조입니다.

// OPC UA 세션 생성 및 구독 등록 실무 패턴
public async Task StartMonitoringAsync(string serverUrl, CancellationToken ct)
{
    var config = new ApplicationConfiguration { /* 보안 인증서 및 클라이언트 설정 */ };
    var endpoint = new ConfiguredEndpoint(null, new EndpointDescription(serverUrl));

    using var session = await Session.Create(config, endpoint, false, "moduin_EdgeCollector", 60000, new UserIdentity(), null);

    // 1초 주기의 구독 컨테이너 생성
    var subscription = new Subscription(session.DefaultSubscription)
    {
        PublishingInterval = 1000,
        PublishingEnabled = true
    };

    // 모니터링할 센서 노드 등록 (데드밴드 설정: 온도 변화 0.5도 이상일 때만 트리거)
    var monitoredItem = new MonitoredItem(subscription.DefaultItem)
    {
        StartNodeId = new NodeId("ns=2;s=AssemblyLine.MachineA.Sensor.Temperature"),
        AttributeId = Attributes.Value,
        SamplingInterval = 500,
        QueueSize = 10,
        DiscardOldest = true
    };

    monitoredItem.Notification += (item, e) =>
    {
        var val = ((MonitoredItemNotification)e.NotificationValue).Value;
        // In-Memory Queue로 안전하게 전달하여 수집 스레드 분리
        DataPipeline.Enqueue(new SensorData(item.ResolvedNodeId.ToString(), val.Value, val.SourceTimestamp));
    };

    subscription.AddItem(monitoredItem);
    session.AddSubscription(subscription);
    await subscription.CreateAsync(ct);
}

5. 통신 단절 대비 세션 자동 복구(Auto-Reconnect) 설계

현장 유지보수 작업 중 스위치 리셋이나 설비 전원 차단 시 세션이 즉시 유실됩니다. KeepAlive 이벤트를 모니터링하여 연결이 끊어지면 기존 세션을 안전하게 폐기하고 지수 백오프 기반으로 백그라운드 재접속을 시도하는 핸들러를 반드시 구성해야 합니다.
