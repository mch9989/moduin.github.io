[스마트팩토리] 중소 제조현장 레거시 PLC 연동을 위한 경량 엣지 데이터 브로커 설계

2026-11-09

목차

  • 1. 현장의 근본 문제와 설계 요건
  • 2. 핵심 아키텍처: 생산자-소비자 채널 및 로컬 페일오버

중소·중견 제조 현장의 MES/스마트팩토리 구축 시 가장 빈번하게 터지는 문제는 상위 시스템의 기능 부족이 아니다. 현장 PLC 설비와 상위 DB(MS-SQL, Oracle) 사이의 통신 단절 및 데이터 유실 처리 부재다.

라인 현장에서는 네트워크 순단이나 상위 DB 서버 재기동이 빈번히 발생한다. 이때 PLC 드라이버가 DB 직접 연결(Insert)을 시도하는 구조라면 커넥션 타임아웃으로 인해 설비 인터락이 걸리거나, 생산 실적 및 센서 시계열 데이터가 통째로 증발한다. 그렇다고 라인마다 수천만 원을 호가하는 외산 OPC 서버나 미들웨어를 도입하는 것은 단가 타산이 맞지 않는다.

이 문제를 해결하고 독립 패키지(SW 라이선스 형태)로 판매 가능한 C# .NET 8 기반의 '스마트팩토리 무손실 엣지 데이터 브로커(Edge Data Broker)' 아키텍처와 구현 메커니즘을 정리한다.

1. 현장의 근본 문제와 설계 요건

현장 설비 데이터 수집기는 단순 통신 라이브러리 조합만으로 끝나지 않는다. 공장 바닥에서 무인으로 365일 돌아가려면 세 가지 조건이 필수적이다.

  1. 프로토콜 격리: LS ELECTRIC(XGT), 미쓰비시(MC Protocol), 지멘스(S7), 모드버스(Modbus TCP) 등 설비별 프로토콜 수집 스레드와 상위 전송 스레드의 완전한 분리.
  2. 로컬 무손실 버퍼링 (Store-and-Forward): 상위망 장애 시 메모리 큐(Channel<T>)에서 로컬 임시 DB(SQLite 또는 암호화 로컬 파일)로 자동 전환되는 페일오버.
  3. 가벼운 풋프린트: 저사양 산업용 미니 PC(IPC, 4GB RAM 수준)에서도 CPU 점유율 2% 미만을 유지하는 윈도우 서비스(Background Worker) 구동.

2. 핵심 아키텍처: 생산자-소비자 채널 및 로컬 페일오버

아키텍처의 중심은 .NET의 고성능 비동기 큐인 System.Threading.Channels다. 수집기(Producer)는 통신 패킷을 큐에 밀어 넣기만 하고 즉시 다음 주기를 폴링하며, 전송기(Consumer)는 네트워크 상태를 감시하며 일괄 트랜잭션으로 처리한다.

[PLC 설비군 (LS/Mitsubishi/Modbus)]
         │ (100ms~500ms 주기 폴링)
         ▼
[수집 엔진 (Protocol Driver)]
         │
         ▼
[메모리 버퍼 (System.Threading.Channels)]
         │
         ├── [정상 상태] ──► [상위 MES REST API / MS-SQL 벌크 인서트]
         │
         └── [통신 두절] ──► [로컬 SQLite 링버퍼 (Store)]
                                    │
                              (망 복구 감지)
                                    ▼
                             (순차 백필 전송 Forward)
