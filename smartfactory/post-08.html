스마트팩토리 예지보전(PdM) 과제를 수행할 때 메인 모터의 진동(가속도)이나 인버터 전력 소비량 데이터는 100Hz~1kHz(초당 수백~수천 회) 단위로 발생합니다. 이 원시(Raw) 데이터를 매 순간 DBMS에 직접 INSERT하면 데이터베이스 커넥션 풀이 즉시 고갈되고 스토리지 I/O 큐가 폭주합니다. 본 글에서는 엣지 게이트웨이 레벨에서 링 버퍼(Ring Buffer)를 활용해 GC 부하 없이 실시간 데이터를 집계하는 아키텍처를 소개합니다.

1. 문제 제기: 고속 진동·전력 센서 데이터와 DB I/O 병목

설비 10대에서 각 1kHz 속도로 쏟아지는 부동소수점(float) 데이터를 상위 관계형 데이터베이스(RDBMS)에 1:1로 밀어 넣는 설계는 현장 엣지 PC의 CPU 100% 포화를 초래합니다. 상위 MES나 클라우드 대시보드가 진정 필요로 하는 것은 밀리초 단위의 미세 떨림 자체가 아니라, **일정 윈도우(예: 1초, 5초) 단위의 피크값(Peak), RMS(실효치), 평균값(Average), 왜도(Skewness)**와 같은 통계적 집계 데이터입니다.

2. 고정 크기 링 버퍼(Circular Buffer)의 메모리 무할당 구조

데이터가 들어올 때마다 new List<float>()를 생성하고 버리는 방식은 .NET 가비지 컬렉터(GC Generation 0/1)를 지속해서 유발합니다. 링 버퍼는 사전에 할당된 고정 크기의 배열 인덱스를 순환 포인터로 덮어쓰므로 힙 메모리 할당(Allocation)이 제로(0)에 수렴합니다.

[PLC / DAQ 디바이스 고속 센서 패킷] (1,000 req/sec)
               │
               ▼
┌──────────────────────────────────────────────┐
│  고정 크기 인메모리 링 버퍼 (Circular Array)   │
│  [Pos 0][Pos 1][Pos 2]...[Pos 999]           │ ◄── Head/Tail 포인터 순환 덮어쓰기
└──────────────────────────────────────────────┘
               │
               ▼ (1초 주기 백그라운드 태스크)
[Zero-Copy RMS / Peak 연산 (Span<float> 활용)]
               │
               ▼ (단 1건의 축약 요약 레코드 생성)
[상위 MES / InfluxDB / PostgreSQL 마이크로 배치 전송]

3. C# ArrayPool과 Span<T>를 활용한 무복사(Zero-Copy) 다운샘플링

C#의 Span<T>과 Memory<T>를 결합하면 버퍼 배열을 쪼개어 복사하지 않고도 메모리 주소 포인터 기반으로 통계 연산을 즉시 수행할 수 있습니다.

public class HighSpeedSensorAggregator
{
    private readonly float[] _ringBuffer;
    private readonly int _capacity;
    private int _head = 0;
    private readonly object _lock = new();

    public HighSpeedSensorAggregator(int capacity = 1000)
    {
        _capacity = capacity;
        _ringBuffer = new float[capacity];
    }

    // 센서 데이터 1건 기록 (락 경합을 최소화한 원자적 갱신)
    public void Push(float value)
    {
        lock (_lock)
        {
            _ringBuffer[_head] = value;
            _head = (_head + 1) % _capacity;
        }
    }

    // 1초 주기로 집계 스냅샷 추출 (힙 할당 없음)
    public SensorAggregatedResult CalculateSnapshotAndFlush()
    {
        ReadOnlySpan<float> dataSpan;
        lock (_lock)
        {
            dataSpan = new ReadOnlySpan<float>(_ringBuffer);
        }

        float sum = 0f;
        float sumSquares = 0f;
        float max = float.MinValue;
        float min = float.MaxValue;

        for (int i = 0; i < dataSpan.Length; i++)
        {
            float val = dataSpan[i];
            sum += val;
            sumSquares += val * val;
            if (val > max) max = val;
            if (val < min) min = val;
        }

        float avg = sum / dataSpan.Length;
        float rms = MathF.Sqrt(sumSquares / dataSpan.Length); // 진동 실효치

        return new SensorAggregatedResult(avg, max, min, rms, DateTime.Now);
    }
}

4. 상위 MES/시계열 DB로의 마이크로 배치(Micro-Batch) Flush 아키텍처

계산된 축약 레코드는 초당 1건 수준으로 감소하므로 엣지 게이트웨이의 네트워크 대역폭과 DB I/O 부하가 99.9% 줄어듭니다. 또한 이상 진동(임계치 초과)이 감지된 순간에만 전후 5초간의 링 버퍼 원시 파형 전체를 파일 형태로 덤프하여 상위 서버에 전송하는 '이벤트 트리거드 로깅' 방식을 병행하면 완벽한 추적성을 보장할 수 있습니다.

5. 현장 엣지 게이트웨이(IPC) 안정성 확보 결론

현장 적용 결과: 진동 주파수 1kHz 환경에서 본 링 버퍼 집계 아키텍처를 도입한 결과, 엣지 산업용 PC(IPC)의 CPU 점유율이 85%에서 4% 미만으로 급감하였으며 1년 연속 가동 시에도 GC로 인한 데이터 유실(Drop)이 전혀 발생하지 않았습니다.
